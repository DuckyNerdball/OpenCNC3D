# Material screen-space reflections

Added 10 November 2026 for the user's shared structure/vehicle material standard. The screen-space query is in `game/screen_reflections_glsl.h`; Dawn3D and RA3D use `game/screen_reflections_post.h`. Authored PBR materials supply their normal, roughness, metallic colour/F0 and dielectric specular level. This does not turn every painted surface into a mirror or replace material maps.

The pass traces the current visible depth buffer and samples the current lit scene before HUD/menus. It uses perspective-correct reconstruction, bounded 72-step rays, five-step intersection refinement, finite surface thickness, edge/distance confidence and a roughness-dependent filtered source with a small cone. Swept depth crossings are essential: accepting only individual samples within surface thickness produced periodic stripes in the thin-emitter test. Track the previous sample's signed depth gap, refine a sign change, then check the refined hit. Do not compare the previous ray position against the next sample's unrelated surface position.

Dawn3D/RA3D write optional material, existing sky contribution and actual shading normal/weight targets alongside lighting. The post pass replaces the existing sky contribution only at valid reflected hits, retaining cavity/specular occlusion, material calibration and rain/haze attenuation. The existing environment remains the fallback. MRT output is compiled only on devices with enough draw buffers; failed optional targets leave the ordinary light chain usable. The first MRT allocation touches texture unit zero, so the lighting source must be rebound before drawing. Never sample the target currently being written. Restore bindings/filters afterward and free optional targets at shutdown.

The existing dynamic vehicle/structure lamp cones also receive a GGX specular response using the same timing, range and occlusion as diffuse lamp lighting. This is needed for bare metal: a diffuse-only lamp cannot produce its physical highlight. Finite-source broadening limits unstable pinprick highlights. Shared lamp specular and visible-scene reflections are complementary.

`CNC3D_SSR_OFF=1` disables the reflection pass for controlled tests. The hidden native probe is `tools/qa/screen-reflections-probe.cpp`, with `tools/qa/check-screen-reflections.py`. It compiles the actual shared GLSL and checks orthographic/perspective projections, three roughnesses, light off/moved/occluded and thin-surface continuity. It draws test geometry only, never edits game assets or installed settings. Reflection sources are restricted to visible screen information: off-screen and hidden geometry cannot be recovered. There is no reflection history to retain stale flashing-light images; normal downstream antialiasing remains separate. Transparent particles are not guaranteed reflection sources.

Algorithm references: [McGuire and Mara, Efficient GPU Screen-Space Ray Tracing](https://jcgt.org/published/0003/04/04/) and [AMD FidelityFX SSSR](https://gpuopen.com/fidelityfx-sssr/). This is a bounded compatibility-renderer implementation, not an integration of AMD's compute pipeline. Native macOS tests and Windows coverage must be recorded separately; compilation or a macOS pass is not Windows visual validation.
